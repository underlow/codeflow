Implement your assigned task: a numbered section of `plan.md` or a file under
`tasks/`. Treat the whole plan as your task only when it contains a single task.

Read the task, then the documents it relies on: `problem.md`, and
`requirements.md` with `design.md`, or `specification.md`, which holds both.
When there are neither, the plan carries the requirements and the technical
approach. Before implementing, inspect the affected code to understand the
current behavior, where the change belongs, and existing mechanisms that solve
all or part of the task. Keep the investigation within the task's scope.

If an input is missing, do the work it does not affect and report the rest. If
yours is the last task, also run the plan's whole-feature checks and update
affected documentation unless the plan assigns them elsewhere.
